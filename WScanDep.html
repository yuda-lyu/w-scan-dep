WScanDep

WScanDep

(async) new WScanDep(fpIn, fdOut) → {Promise}

Description:

  • 依賴套件漏洞掃描

    經ensureBins取得syft、grype、osv-scanner、ex-sbom(依bin/manifest.json校驗SHA-256與大小，首次使用時下載並存於快取)，掃描指定專案之依賴套件，並將檢測數據、markdown報告、連鎖更新清單與ex-sbom各漏洞套件截圖輸出至指定資料夾，僅支援Windows

    掃描範圍只算dependencies：掃描對象為網頁前後端服務或編譯出之應用程式(app)，只有dependencies所提供者(程式碼，以及這些套件所附之執行檔)會被服務或app實際使用，才算數；devDependencies之開發與建置工具不是服務，也不會包入app執行，不在範圍(其風險應由執行機自行掃描或以防毒軟體處理)。作法為隔離安裝(fdOut/test)只裝正式相依樹(npm install --omit=dev)：devDependencies及其所附之執行檔(如vite帶入之esbuild.exe)不落地、不入SBOM，syft、grype、osv-scanner、ex-sbom與待更新套件清單(updateList)皆只及正式相依樹；同時為正式套件之相依者(如vue為正式套件之對等相依，即使package.json亦列於devDependencies)照收。不提供掃描開發工具之開關。result.json之scope為'dependencies'，result.md亦寫明範圍。此範圍不受呼叫端npm設定影響(隔離安裝之子行程環境移除會使npm裝入dev套件之npm_config_include、npm_config_production、npm_config_dev、npm_config_also，不改呼叫端之process.env)，安裝後若隔離資料夾內仍有dev套件(如使用者層或全域.npmrc設了include=dev)即reject，不輸出result.*。

    隔離安裝沿用呼叫端專案之倉庫設定：npm之專案層.npmrc取自安裝目錄(fdOut/test)，讀不到呼叫端專案層之.npmrc，專案方常把registry=只寫在專案層(自有套件只發布於私有倉庫)，隔離安裝若不沿用，會改由使用者層或預設倉庫解析而與專案實際安裝不符。故於呼叫端專案目錄(fpIn所在處)執行npm config list --json取npm之生效值(專案層、使用者層、全域層、環境變數合併後者)，只挑registry與各@scope:registry，寫入fdOut/test/.npmrc(該檔每次執行重寫，未取得任何倉庫設定時刪除)，不改呼叫端之任何設定檔與process.env。只帶倉庫位址：不帶include、production、dev、also、omit等安裝集合設定(掃描範圍仍為dependencies)，不帶認證值(_authToken、_auth、username、_password，網址內嵌之帳密亦去除；認證依主機鍵存於使用者層者npm本來就讀得到)，TLS相關設定(cafile、strict-ssl)與代理設定亦不帶。取得生效設定失敗(逾時、離開碼非0、輸出非JSON、無法啟動)即reject，不改用預設倉庫(以免掃描結果與專案實際安裝不符)，錯誤訊息只寫原因、不含npm之輸出與設定值(成功時log列出沿用之倉庫位址，已去除網址內嵌之帳密)；時限由環境變數W_NPM_CONFIG_TIMEOUT(秒，正數，至多2147483)指定，預設60，值不為正數時於任何下載與寫入前reject。

    外部執行檔不含於npm包，快取預設為套件根之bin-cache/，可由環境變數W_BIN_CACHE改位置(多個專案共用同一份)；W_BIN_MIRROR指定離線鏡像，W_BIN_OFFLINE=1時不連網；部署前可預先呼叫WScanDep.ensureBins()，見README〈外部執行檔〉。 ex-sbom服務埠自18080起自動選用；同時掃描多個專案須以不同node程序、不同fdOut執行

    npm install之時限由環境變數W_NPM_INSTALL_TIMEOUT(秒，正數，至多2147483)指定，預設1200(20分鐘)，逾時即結束整個安裝子行程樹並reject含「逾時」之錯誤；值不為正數時於任何下載與寫入前reject。 syft、grype、osv-scanner之單次執行時限各由環境變數W_SYFT_TIMEOUT(預設3600秒)、W_GRYPE_TIMEOUT(預設1800秒，首次執行含下載漏洞資料庫)、W_OSV_SCANNER_TIMEOUT(預設600秒，osv-scanner對markdown與json各跑一次、各自計時)指定(秒，正數，至多2147483)，逾時即結束該工具之整個子行程樹並reject含「逾時」與工具名之錯誤(此時不寫出result.*)；值不為正數時於任何下載與寫入前reject。預設值依實測(1364個元件：syft暖6秒、冷81秒、本機被他程序占滿時519秒；grype冷資料庫86秒；osv-scanner每次3.5秒內)訂定，取實測最大值之5倍以上。

    ex-sbom之任何失敗(啟動失敗、截圖期間意外結束、分析SBOM失敗等)只作廢截圖：仍resolve 'ok'並寫出syft、grype、osv-scanner之結果，result.json之exsbom.ok為false、exsbom.error為原因(截圖期間意外結束時附ex-sbom.log之fatal error/panic及其後數行)，並刪除fdOut/pics；呼叫端以exsbom.ok判斷是否採用截圖。 ex-sbom v0.2.0對相依關係含循環之SBOM會無限遞迴而結束(npm常見，如es-abstract與string.prototype.trim互相依賴)：本套件上傳前於副本剔除構成循環之關係(syft原檔不動，grype與osv-scanner不受影響)，剔除者列於result.json之exsbom.removedRelationships([{ from, to, relationshipType, spdxElementId, relatedSpdxElement }]，無循環為[]，截圖失敗且尚未算出時為null)。

import wsd from 'w-scan-dep'

    // => 'ok'

    // 產出於fdOut:

    //   result.md 掃描報告
    //   待更新套件.md 連鎖更新清單
    //   pics/*.png ex-sbom拓撲總覽與各漏洞套件截圖(截圖失敗時無)

    // 部署前預先取得掃描工具(連網機器設W_BIN_CACHE=<資料夾>後執行，該資料夾即可作為離線鏡像W_BIN_MIRROR):
    // let bins = await wsd.ensureBins()

}
test()
    .catch((err) => {
